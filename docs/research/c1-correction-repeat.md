# C1 补充实验：纠错后的下一次修改

服务从两份 TOML 中选一份读取超时。改版交换了生效文件，旧文件仍可编辑。准备任务要求把 30 改为 60，后续任务在新会话中把 60 改为 90。评分器独立执行服务、核对配置和启动代码。模型为 DeepSeek-V4-Flash。

## 自然准备会话

从第三轮两个旧版本的单写学习快照各启动两次，仅提供默认记忆。旧入口为 settings.toml 的两次均先改旧文件，独立运行仍为 30。旧入口为 app.toml 的两次均在写前看到启动代码，一次只改对文件，另一次依次改了旧、新两个文件，两次最终都是 60。双写之间没有运行服务，所以单列为探索性起点，不能计为运行失败触发的返工。

## 已观测到运行失败的四份起点

第三轮完整历史组有四条先误改、运行得到 30、再修正到 60 的轨迹，每个迁移方向两条。原组关闭了记忆写入。本轮在其旧版本学习笔记副本上，用默认维护流程重新提取各条已存会话的记忆，并用原评分记录重建仓库。这里比较的是同一轨迹的不同记忆处理结果；四个起点并非四个全新项目。

每个起点复制为三个独立会话。默认组保留原样，遗忘组撤下新旧入口提示，更新组仅保留正确入口。其余笔记保留。settings-r1 的遗忘组同时移除了超时值笔记中的路径，保留值和验证命令。app-r1、app-r2 和 settings-r1 的默认笔记中已有相互矛盾的入口；settings-r2 只有旧入口，本轮为其更新组人工写入正确提示。探索性的 app-2 同样需要人工补入。各方向使用各自原学习快照，方向差异也可能来自原笔记措辞和验证偏好。

下表中的单元格依次为首次实际写入、写前成功读取次数、独立运行值。读目录计入读取。双写表示同一次工具操作改了两份文件。

| 起点（前缀为旧入口） | 默认 | 遗忘 | 更新 |
|---|---|---|---|
| app-r1 | correct / 5 / 90 | correct / 4 / 90 | correct / 3 / 90 |
| app-r2 | correct / 3 / 90 | correct / 4 / 90 | correct / 4 / 90 |
| settings-r1 | correct / 2 / 90 | correct / 4 / 90 | correct / 3 / 90 |
| settings-r2 | correct / 5 / 90 | correct / 5 / 90 | correct / 7 / 90 |
| app-2 | correct / 4 / 90 | correct / 4 / 90 | correct / 4 / 90 |

correct 指首次仅命中生效配置，inactive 指首次改动旧配置，both 指首次同时修改两份配置。app-2 是本轮自然双写的探索性对照，其余四行是主比较。

## 主比较成本与结果

| 组别 | 首次命中 | 最终 90 | 写前读取总数 | 工具调用总数 | Agent token 总数 | 记忆 token 总数 |
|---|---:|---:|---:|---:|---:|---:|
| default | 4 | 4 | 15 | 30 | 49244 | 8369 |
| forget | 4 | 4 | 17 | 39 | 57725 | 8844 |
| update | 4 | 4 | 17 | 34 | 51218 | 7264 |

token 计入第四会话请求的输入和输出，准备和重放提取单列在原始日志中。每个起点每种处理只运行一次。原始 JSONL、评分、各组输入快照与运行脚本保存在本机项目目录 `.swe-agent/experiments/c1-correction-02/`。

主比较中，首次命中后又写了闲置配置的次数为默认组 1/4、遗忘组 3/4、更新组 0/4。遗忘组还有一次在仓库根目录新建了 service-timeout.md。三个默认笔记已含正确提示的起点，默认与更新的写前读取总数都是 10；逐对比较，更新组一次少读、两次多读。尚未观察到停用旧提示能稳定节省首次检查。

后续优先验证准备阶段的错误是否会被写成长期记忆。有一次服务实际仍输出 30，后台却保存了超时已改为 60 的笔记。可固定同一条误改轨迹，比较提供实际运行输出与仅提供文件回读时的记忆写入，再用入口稳定的仓库检查是否误伤有效经验。
