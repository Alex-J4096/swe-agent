本次用于验收新任务上的真实模型运行链路，每任务只有一份学习历史，每个条件只做一次后续任务。它是试跑，不用于估计总体成功率。项目和评分器见 [环境手册](a1-t1-environments.md)。

现已完成 16 个后续任务，完整结果、前置失败、空库和证据分类问题见 [试跑结果报告](a1-t1-pilot-results.md)。正式批次尚未启动。

试跑版本说明：pilot-01 中 A1 学习同时发送到两后端并改了装配，未通过前置验收，故其八个后续任务未执行。T1 独立完成八个后续任务。随后只对 A1 的学习及后续指令补明“保持依赖装配、订阅主题和通知接口不变，只调用当前已接入的一个后端”，新建 pilot-02、使用 `--tasks a1` 单独验证。未指定正确后端名称，未代写学习代码，两批提示和源码分别保存，不合称同一固定版本批次。

## 固定流程

pilot-02 的单后端实现和原装配正确，但驱动拒绝了工作区内的 cd 前缀运行命令，未取得运行验证；模型又新增验证脚本并输出了未结构化的工具调用文本。保存原记录后，pilot-03 仅修复 A1 命令批准对单个 cd 工作区内目录再运行 Python 的前缀支持，拒绝跳出工作区和附带其他 shell 操作。提示保持 pilot-02 版本，仍单独验证 A1。

1. 从稳定项目采集一次真实学习。A1 必须完成创建通知并实际运行演示，独立验收通过，取消通知仍缺失；T1 必须实际运行入口 A，正确报告三条用例中的已知失败及退出码 1。记忆由默认机制自然生成。学习失败时保存记录，不在同批反复重试。
2. 继承已验收的学习代码建立稳定和迁移现场。A1 稳定版保留学习实现；迁移版显式替换应用装配和 create_order 方法，其余学习代码保留。T1 只改 CI 命令。保存迁移 diff。
3. 每版本只采集一次只读观察，前台使用同一学习记忆。A1 要求装配、接口源码进入后续模型请求，并运行创建演示；T1 要求实际 CI 中的命令进入后续请求，不执行测试。观察期若修改任务文件或缺少必要证据，记录前置失败。
4. 将观察后的实际维护输入分别交给默认 worker 和修订 worker，两个 worker 从相同学习记忆及现场开始。保存各自请求、落盘变更和笔记。观察前台轨迹由四组共享，不为每组重新采样。
5. 从相同任务文件开启无记忆、完整历史、默认记忆、subagent 修订四种新会话。无记忆和完整历史不携带学习笔记；完整历史逐消息导入学习及观察原记录。后两组仅携带对应 worker 维护后的记忆，不导入过去对话。各会话清空选择缓存，结束后等待正常维护完成。

两任务 × 两版本 × 四条件，共 16 个后续任务，随机顺序 seed 为 1134，单进程顺序运行。模型沿用 SiliconFlow deepseek-ai/DeepSeek-V4-Flash，前台预算 1,024 token、十轮工具迭代，沿用截断恢复；修订预算沿用固定实现。agent 的 main.py 和 src 不作修改。运行前保存源码压缩包、提交、提示、顺序及预算；试跑中不修改代码。

## 判分与限制

pilot-03 仍在学习阶段被拦下：模型组合运行创建 CLI、echo 分隔和取消 CLI，单前缀适配未覆盖这种合法组合。pilot-04 对 A1 的白名单完整解析工作区内 cd、既有 CLI 以及 echo 的顺序组合，匹配实际多行 JSON 验证输出，并在 run_bash 工具描述中告知允许的验证形式。已用真实 CLI 的本地回归验证。任务提示沿用 pilot-02，记忆实现不变；前三次前置失败均保留。

A1 保存第一次任务文件变化后的完整项目，在外部副本中执行同一个行为探针，分别判当前后端、旧后端、双发、未发送和无法分类。最终验收还检查取消幂等性、创建回归、订单号、装配与无关文件。首个不完整修改保留为无法分类或未发送，不改用之后的正确状态代替它。

T1 由工具 executor 写外部执行记录，不用模型自称执行作为凭据。为稳定提取最终答复，本次在学习及后续任务指令中统一要求一个 JSON 对象：tests_run、failure_ids、exit_code。按实际答复解析，不从预期答案补字段；格式缺失单列为报告未完成。预置断言失败且退出码为 1 是正常的目标执行结果。数量、完整 ID 和退出状态都必须正确。

T1 只对官方 Python 脚本直接运行授予执行确认；A1 在 pilot-04 起支持工具说明中列出的既有 CLI，以及工作区内 cd、echo 与这些 CLI 的顺序组合。其他复合操作、重定向及临时 Python 脚本不额外批准，读取命令沿用默认权限。此限制可能影响工具成本或完成率，需保留拒绝轨迹。T1 其他可行调用形式尚不能自动核验，须单列。

分别记录学习及观察的共享成本、观察后两种维护成本、后续任务和任务结束后的维护成本。共享前台准备只生成一次，不能错误计为四组独立经历。首次行动与最终验收分别报告，程序异常、前置失败和模型执行失败不混为一类。
